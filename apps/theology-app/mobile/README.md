# Study Desk — native (Expo / React Native)

iPad-first theology study client with **true native scrolling** (`FlatList` / `ScrollView` → `UIScrollView`). Sibling of the web frontend; shares the same mock lib contract.

## Target device constraint — pinned to Expo SDK 54

The target iPad is an **iPad mini 4 (`iPad5,1`)** on **iPadOS 15.8.8**, its final OS. Two
separate ceilings apply:

| Limit | Imposed by | Max SDK |
|-------|-----------|---------|
| iOS floor raised 15.1 → 16.4 in SDK 56 (dropped iPad mini 4 / Air 2) | the device | 55 |
| App Store Expo Go is **54.0.2**, supports SDK 54 only | Expo Go | **54** |

Expo Go for SDK 55 was submitted in May 2026 but never cleared Apple review, so SDK 55 builds
cannot be opened in Expo Go at all. **SDK 54 satisfies both limits** and is what this project targets.

Do not run `expo upgrade` or bump `expo` / `react-native` past 54.x — see [`AGENTS.md`](AGENTS.md).

## Toolchain requirements

| Requirement | Needed | Note |
|-------------|--------|------|

| Xcode | 16.1+ | only needed for the sideload path, not Expo Go |

| Locale | UTF-8 | CocoaPods fails without it |

One-time setup on the Mac:

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
echo 'export LANG=en_US.UTF-8' >> ~/.zshrc
```

## Quick start (Expo Go — no paid Apple account)

1. On the iPad: install **Expo Go** (54.0.2) from the App Store. It requires iOS 15.1+, so it
   installs fine on the mini 4.
2. Start Metro on whichever machine you are developing from:

```bash
cd apps/theology-app/mobile
nvm use 24
npm install
npm start
```

3. On the iPad (same LAN / Tailscale): open Expo Go → enter the `exp://<host>:8081` URL printed
   in the terminal, or scan the QR code.

Allow **Local Network** when iOS prompts.

Verify the server is offering the SDK that Expo Go expects — a mismatch is what produces
*"project requires a newer version of Expo Go"*:

```bash
curl -s -H "Expo-Platform: ios" http://localhost:8081/ | rg -o '"sdkVersion":"[^"]*"'
# expected: "sdkVersion":"54.0.0"
```

If it reports anything else, a **stale Metro from a previous SDK is still running** — Expo
resolves the SDK at server start, so it will keep serving the old version until restarted.
Find and kill it with `lsof -nP -iTCP:8081 -sTCP:LISTEN`.

> On this Mac, Cursor's extension host also listens on `127.0.0.1:8081`. That is loopback-only
> and does **not** block Metro, which binds `0.0.0.0`. If Expo offers to switch to port 8082,
> answer **no**.

### Persistent Metro on the homelab

```bash
# install + enable user service
mkdir -p ~/.config/systemd/user
cp deploy/study-desk-metro.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now study-desk-metro.service
journalctl --user -u study-desk-metro.service -f
```

Metro listens on `0.0.0.0:8081`.

> **The homelab has its own checkout.** It is still on SDK 57 and will serve
> `"sdkVersion":"57.0.0"`, which Expo Go rejects. Before using it, push this SDK 54 change,
> then on the homelab run `git pull && nvm use 24 && npm install` and
> `systemctl --user restart study-desk-metro.service`.

## Free sideload (standalone app icon, no $99)

Uses a free Apple ID **Personal Team**. Certificate lasts **7 days**; re-run from Xcode weekly (or refresh with AltStore/SideStore).

1. On a Mac with Xcode: clone this repo (or sync `apps/theology-app/mobile`).
2. Install deps and generate the native project:

```bash
cd apps/theology-app/mobile
nvm use 24
npm install
npx expo prebuild --platform ios --clean
cd ios && pod install
```

`ios/` is gitignored and fully regenerated by `prebuild`, so it is always safe to delete and
rebuild if the native project drifts. Verify the target after prebuild:

```bash
rg -o "IPHONEOS_DEPLOYMENT_TARGET = [0-9.]+" ios/StudyDesk.xcodeproj/project.pbxproj | sort -u
# expected: IPHONEOS_DEPLOYMENT_TARGET = 15.1
```

3. Open `ios/StudyDesk.xcworkspace` (or the generated workspace name) in Xcode.
4. **Signing & Capabilities** → Team: your Apple ID (Personal Team).
5. Bundle ID must stay unique: `arpa.home.studydesk` (already set in `app.json`).
6. Select your iPad → Run (▶).
7. On the iPad: **Settings → General → VPN & Device Management** → trust the developer profile.

Weekly refresh: plug in (or use wireless debugging) and Run again from Xcode.

Limit: free accounts can install up to **3** apps this way.

### Daily workflow — you do NOT rebuild for JS changes

The sideloaded debug build contains no bundled JS; it fetches from Metro at launch, so Fast
Refresh works exactly as it did in Expo Go. Edit a `.tsx`, save, see it on the iPad.

Rebuild from Xcode only when:

- a dependency with native code is added or changed
- `app.json` changes (plugins, icons, `infoPlist` / ATS entries)
- the deployment target or bundle ID changes
- the 7-day certificate lapses

### Which Metro does the sideloaded app talk to?

**The Mac you built from — not the homelab.** The RN build phase writes the build machine's
LAN IP into `ip.txt` inside the `.app`, and `RCTBundleURLProvider` resolves in this order:

1. `RCT_jsLocation` (on-device override, normally unset)
2. `ip.txt` — used only if Metro actually answers there
3. otherwise the bundle fails to load

So while developing natively, run Metro **on the Mac**:

```bash
cd apps/theology-app/mobile
nvm use 24
npm start
```

Note that `REACT_NATIVE_PACKAGER_HOSTNAME` does *not* influence `ip.txt` — `react-native-xcode.sh`
derives that from `ipconfig getifaddr`. The variable only affects the Metro server itself, which is
why it is set in the homelab systemd unit.

The homelab Metro service (`192.168.1.156:8081`) still serves the **Expo Go** path and the web
frontend. If you want the sideloaded app to use it instead, the build needs a config plugin to
write that IP into `ip.txt`, since `ios/` is regenerated on every prebuild.

If the Mac's DHCP lease changes its IP, just Run again from Xcode — `ip.txt` is rewritten each build.

## Networking / ATS

`app.json` already allows insecure HTTP to:

- `*.home.arpa` (including `theology.home.arpa`)
- `192.168.1.156`
- local networking (`NSAllowsLocalNetworking`)

Caddy should expose the future FastAPI backend as `http://theology.home.arpa` → `:8002`.

Override API base at runtime:

```bash
EXPO_PUBLIC_API_BASE=http://192.168.1.156:8002 npm start
```
